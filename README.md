# WordPress 博客系统 — 全栈测试实战

## 📖 项目概述

本项目以**阿里云 ECS + Docker 部署的 WordPress 6 博客系统**为被测对象，独立完成从测试计划、用例设计、执行到报告输出的**功能、接口、性能、安全、UI 自动化**全流程质量保障。
- **一句话总结**：设计 48 条功能用例、32 条接口用例，JMeter 压测 TPS 提升 94%，发现 4 项安全漏洞，搭建 Selenium + pytest 自动化回归脚本并输出完整测试资产。

## 🛠 技术栈

`Linux` `Docker` `MySQL` `Postman` `Newman` `JMeter` `OWASP ZAP` `Selenium` `Python` `pytest` `Git` `阿里云 ECS`

## 🔍 核心亮点

- **接口自动化链**：Postman → Runner 集合执行 → Newman 生成 HTML 报告，实现接口回归自动化  
- **性能对比实验**：无缓存 vs WP Super Cache，量化缓存对系统吞吐量和响应时间的提升效果  
- **漏洞精准定位**：发现评论区存储型 XSS（高危），并能区分不同输出点的编码差异（标题安全、个人说明部分过滤、评论区未过滤）  
- **误报分析**：ZAP 报告 SQL 注入告警经人工验证证据为空，判定误报并记录分析过程  
- **UI 自动化折中策略**：因古腾堡编辑器动态加载导致定位不稳定，改为编辑已有文章 + URL 验证，保证脚本可维护性  

## 🧪 测试复盘（踩坑与解决记录）

### 环境搭建
- **Docker 镜像拉取超时** → 配置阿里云 Docker 镜像加速器，更换公共 DNS  
- **网站访问极慢** → 升级带宽至按流量计费 100Mbps，安装 WP Super Cache 缓存插件  
- **应用密码无法生成**（提示需要 HTTPS） → 修改 `wp-config.php`，添加 `WP_ENVIRONMENT_TYPE` 为 development 并强制启用应用密码  

### 功能测试
- **编辑删除他人文章权限失效** → 确认为严重缺陷，提交 GitHub Issue 跟踪  
- **草稿状态异常可见** → 一般缺陷，建议检查查询条件  
- **超长评论未拦截** → 一般缺陷，建议前后端双重校验  

### 接口测试
- **Runner 集合执行时部分接口 401** → 将创建文章默认状态从 `draft` 改为 `publish`，在 API-001 中自动设置稳定 `base_post_id`  
- **评论接口重复提交被拦截** → 在 Pre-request Script 中动态生成带时间戳的评论内容  
- **用户创建接口用户名冲突** → 使用随机数动态生成用户名  
- **文件上传接口无法自动化** → Postman Runner 不支持本地文件路径，改为手工验证  

### 性能测试
- **JMeter 请求 URL 格式错误（100% 异常）** → 禁用 HTTP 请求默认值，直接在请求中填写 IP 和端口  
- **100 并发时 CPU 打满、SSH 断开** → 阿里云控制台强制重启 ECS，降低并发重测，限制 PHP-FPM 子进程数为 20  
- **有缓存下 100 并发“响应时间先升后降”** → 分析为缓存预热现象，首次请求动态生成后命中静态缓存  

### 安全测试
- **ZAP 扫描报告 SQL 注入告警** → 人工复现无异常，证据字段为空，判定误报  
- **XSS 测试结果不一致** → 评论区弹窗（高危），个人说明处 `<script>` 标签被剥离（安全），精准记录输出编码差异  

### UI 自动化
- **pip 安装依赖 SSL 错误** → 切换清华镜像、升级 pip、离线安装 `.whl` 文件  
- **Chrome 浏览器未找到** → 改用 Edge + `webdriver-manager` 自动下载驱动  
- **古腾堡编辑器标题定位反复超时** → 尝试 JS 注入、XML-RPC、REST API 均受阻后，改为编辑已有文章（`post.php?post=5`），仅验证 URL 即判定通过，保证脚本稳定  
- **登录断言失败**（等待“仪表盘”超时） → 改为等待 `#wpadminbar` 后台工具栏出现  

## 🚀 快速开始

### 1. 克隆仓库
```bash
git clone https://github.com/dizzychow/wordpress-testing-project.git
cd wordpress-testing-project
```

### 2. 安装 UI 自动化依赖
```bash
pip install selenium pytest pytest-html webdriver-manager
```

### 3. 修改配置
编辑 `UI自动化测试/conftest.py`，替换为你的 WordPress 站点信息：
```python
BASE_URL = "http://你的公网IP"
ADMIN_USER = "管理员用户名"
ADMIN_PASS = "管理员密码"

### 4. 运行 UI 测试
```bash
cd UI自动化测试
pytest
```

### 5. 查看报告
用浏览器打开 `UI自动化测试/report.html`

### 6. 导入 Postman Collection
将 `` 导入 Postman，配置环境变量即可运行。
